# 50. AX: AI 에이전트와 자동화로 일한 방식

> 이 프로젝트는 기획자가 **AI 코딩 에이전트(Claude Code)**와 함께 진행했습니다. 아래는 사람이 맡은 일, AI가 맡은 일, 그리고 AI 결과물을 믿을 수 있게 만든 자동 검증 장치를 그대로 정리한 기록입니다.

## 1. 역할 분담

| 단계 | 사람(기획자) | AI 에이전트 | 결과물 |
|---|---|---|---|
| 문제·범위 정의 | 가상 요구사항, 금지사항(운영 접속 금지, 실제 연동 표현 금지), 검증 기준 10개 작성 | – | 작업 지시서 (요구사항·제약·산출물 목록) |
| 현황 분석 | 확인할 대상 지정 ("기존 응답 필드를 추측하지 말 것") | 저장소 구조·코드·설정 분석, 문서와 다른 점 보고 | [01](01-current-structure.md) |
| 외부 조사 | 참고 대상 지정 (카카오뱅크 공개 가이드, 채용 공고) | 공개 페이지 열람·요약, 법령 조문 검색 | [08](08-kakaobank-guide-reference.md), [40](40-compliance-analysis.md), [00](00-job-fit.md) |
| 정책 결정 | 1차 보고에서 가정 정책 확인, 범위를 넓히는 정책은 임의로 추가하지 않게 함 | 선택지와 근거 제시 | [12 ADR](12-decision-log.md) |
| 구현 | 결과 검토 | 코드·테스트·모의 서버·스크립트 작성 | 소스 |
| 검증 | 검증 기준 정의 | 테스트와 E2E 실행, 실패 원인 분석·수정 | [07](07-traceability-and-tests.md) |
| 문서화 | 독자와 목적 지정 ("서버 개발자처럼, 기획자 관점") | 초안 작성, 코드와 일치하는지 자동 점검 | docs 전체 |

## 3. AI 결과물을 믿을 수 있게 만든 장치

AI가 만든 코드와 문서는 **틀릴 수 있다는 전제**로 다뤘습니다. 이번 작업에서 실제로 잡아낸 문제들입니다.

| 발견한 문제 | 무엇이 잡았나 | 교훈 |
|---|---|---|
| 탈퇴 정리 코드의 옵션(`clearAutomatically`) 때문에 **탈퇴가 204를 응답하고도 DB에 반영되지 않던 버그**(AI가 작성한 코드) | E2E S1의 "탈퇴 → 재로그인" 단계 | 단위 테스트만으로는 놓치는 트랜잭션 문제를 실제 흐름 테스트가 잡음 |
| 실습 실행과 테스트가 같은 저장소를 공유해 남은 상태가 테스트에 영향 | JUnit 전체 실행 | 환경 격리도 설계 대상 (테스트 DB 분리, 매 테스트 초기화) |
| 기존 팀 코드의 JWT가 같은 초에 동일하게 발급돼 로그아웃 간섭 | 게이트 테스트 순서 의존 실패 | 발견했지만 팀 코드라 수정하지 않고 보고 ([01 §1.9](01-current-structure.md)) |
| Python HTTP 서버가 역방향 DNS 조회 때문에 기동이 멈춤 | 헬스체크 실패 원인 추적 | 환경 문제를 '코드 문제'로 오인하지 않기 |
| 법령 조문 번호가 기억과 다를 위험 | 웹 검색으로 출처 확인, 확인하지 못한 부분은 문서에 명시 | AI가 "아는 것처럼" 쓴 사실은 출처로 검증 |
| 같은 요청을 두 번 취소했을 때 응답의 `endedAt`이 서로 다름 (Linux 시계 나노초 vs DB 마이크로초) | **GitHub Actions CI의 E2E** (로컬 macOS에서는 재현되지 않음) | 다른 실행 환경에서 자동으로 검증하는 것 자체가 품질 장치. 고친 뒤 회귀 테스트로 고정 |
| 테스트 로그인 성공 코드(`TEST_LOGIN_SUCCESS`)가 API 명세에 빠져 있었음 | `check_docs.py` 첫 실행 | 문서 품질도 자동 검사 대상. 사람이 놓친 누락을 실제로 잡아냄 |

## 4. 측정 (이 PC, 2026-11-02)

| 항목 | 값 |
|---|---|
| JUnit | 35개 |
| E2E | 52개 검증 실행 약 7초 (서버 기동 제외, TIMEOUT 시나리오의 의도된 대기 약 3초 포함). `run-lab.sh --e2e`는 서버 기동까지 포함해 약 1분 |
| 문서 점검 | `check_docs.py` 1초 이내 |

※ 사람이 직접 했을 때의 소요 시간은 측정하지 않았습니다. 그래서 "몇 % 단축" 같은 수치는 쓰지 않습니다.
