# 11. 요구사항 정의서

> 요구사항을 정책([12](12-policy-definition.md)), 화면([14](14-screen-spec.md)), API([04](04-api-spec.md)), 검증([07](07-traceability-and-tests.md))과 ID로 연결했습니다.
> 우선순위: **M** = Must(이번 범위 필수), **S** = Should(있으면 좋음), **기획** = 이번엔 기획만 함.

## 기능 요구사항

| ID | 요구사항 | 상세 | 우선 | 정책 | 화면 | API | 상태 |
|---|---|---|---|---|---|---|---|
| REQ-01 | 가입 직후 선택형 안내 | 신규 가입이면 1회 안내. [지금 하기] / [나중에 할게요] | M | POL-01 | SC-01 | 로그인 응답 `isNewUser` | 데모 구현 |
| REQ-02 | 마이페이지 본인확인 영역 | 미확인이면 [본인확인하기], 완료면 배지와 완료 시각 | M | POL-01·08 | SC-02, SC-08 | `GET /members/me` | 구현 |
| REQ-03 | 미확인 회원 이용 보장 | 본인확인 여부로 기능을 제한하지 않음 | M | POL-02 | – | – | 구현 |
| REQ-04 | 요청 생성·이어하기 | 진행 중이면 같은 요청으로 이어가고, 끝났으면 새로 만듦 | M | POL-03 | SC-03 | `POST .../identity-verifications` | 구현 |
| REQ-05 | 결과 확인 | 복귀하면 서버가 기관에 직접 조회해 반영. 진행 중이면 2초 간격으로 다시 확인 | M | POL-05 | SC-05 | `GET .../{id}` | 구현 |
| REQ-06 | 유효시간·만료 | 5분이 지나면 만료. 만료 후 성공은 인정하지 않음 | M | POL-04 | SC-07 | – | 구현 |
| REQ-07 | 명시적 취소 | 진행 중일 때만 [취소] 노출. 닫기는 보류 | M | POL-06 | SC-05 | `POST .../{id}/cancel` | 구현 |
| REQ-08 | 지연 안내·자동 재확인 | 기관 장애·지연은 실패가 아닌 '지연'으로 안내 | M | POL-07 | SC-05 | 503·502 처리 | 구현 |
| REQ-09 | 완료 이후 처리 | 재인증 요청 시 '이미 완료' 안내. 로그인마다 묻지 않음 | M | POL-08 | SC-08 | 409 처리 | 구현 |
| REQ-10 | 탈퇴 연동 | 진행 중 요청 취소, 확인 상태 파기 | M | POL-09 | – | `DELETE /members/me` | 구현 |
| REQ-11 | 결과 위·변조 방지 | 결과의 전자서명과 요청 일치를 확인한 뒤에만 반영 | M | POL-05 | – | – | 구현 |
| REQ-12 | 인증 전 고지 | 이동하기 전에 목적, 저장 항목(확인 여부·시각), 소요 시간 안내 | S | POL-10 | SC-03 | – | **기획** |
| REQ-13 | 본인 요청만 접근 | 다른 회원의 요청은 '없는 요청'으로 응답 | M | POL-11 | – | 404 | 구현 |
| REQ-14 | 결과 화면 | 성공·실패·취소·만료별 문구와 다음 행동 | M | POL-12 | SC-06, SC-07 | – | 데모 구현(단순화) |

## 비기능 요구사항

| ID | 요구사항 | 기준 (실습 가정) | 검증 |
|---|---|---|---|
| NFR-01 | 응답 시간 | 결과 확인 API 최대 약 3초 (기관 응답 대기 상한) | E2E 지연 시나리오 |
| NFR-02 | 일관성 | 같은 요청에 결과가 동시에 여러 개 도착해도 계정 반영은 1회 | 동시 처리 테스트 |
| NFR-03 | 추적성 | 요청마다 생성 → 확정까지 감사 로그로 추적 가능 | [30](30-api-operations-manual.md) |
| NFR-04 | 실습 격리 | 실습 서버는 실제 인증기관·운영 DB에 연결할 수 없음 | 기동 안전장치 테스트 |

## 범위 밖 (이번에 하지 않는 것)

- 본인확인 완료 회원 혜택 (서비스 정책 결정 필요)
- 실제 본인확인기관 계약·연동, 인증 수단 선택 UI
- CI 기반 중복 가입 차단, 계정 병합
- 네이티브 앱 화면 개발 (화면설계서와 웹 데모로 대체)
