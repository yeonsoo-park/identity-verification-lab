# 12. 정책 정의서

> 이 문서는 기능의 **규칙**을 정합니다. 화면설계서([14](14-screen-spec.md))와 API([04](04-api-spec.md))는 여기서 정한 정책 ID(`POL-xx`)를 근거로 만들어집니다.
> 상태 전이와 예외 처리의 시스템 동작은 [03 상태·예외 상세](03-policy-and-exceptions.md)에 있습니다.
> 숫자는 모두 **실습용 가정**입니다.

## 정책 요약

| ID | 정책 | 한 줄 정의 |
|---|---|---|
| POL-01 | 대상과 진입 시점 | 모든 회원이 **선택적으로** 할 수 있다. 진입점은 가입 직후 1회 안내와 마이페이지 상시 진입 두 곳 |
| POL-02 | 미확인 회원의 이용 | 미확인이어도 **어떤 기능도 제한하지 않는다** |
| POL-03 | 진행 중 요청 | 회원당 진행 중 요청은 **1건**. 다시 누르면 새로 만들지 않고 **이어서 진행** |
| POL-04 | 유효시간 | 요청 후 **5분** 안에 인증을 마쳐야 한다 |
| POL-05 | 결과 판정 | **서버가 인증기관에 직접 확인한 결과**만 인정한다. 앱이 전달한 값은 쓰지 않는다 |
| POL-06 | 취소와 이탈 | **'취소' 버튼만 취소**다. 화면을 닫는 것은 취소가 아니라 보류다 |
| POL-07 | 지연·장애 | 결과를 확인하지 못한 것은 **실패가 아니다**. '지연'으로 안내하고 자동으로 다시 확인한다 |
| POL-08 | 완료 이후 | 한 번 확인되면 **다시 인증하지 않고**, 로그인할 때마다 묻지 않는다 |
| POL-09 | 탈퇴 | 탈퇴하면 진행 중 요청을 취소하고 확인 상태도 파기한다. 재가입하면 미확인부터 |
| POL-10 | 개인정보 | 저장하는 것은 **확인 여부와 시각뿐**. 실명·CI·주민번호를 받지 않고 프로필을 덮어쓰지 않는다 |
| POL-11 | 접근 권한 | 인증 요청은 **본인만** 조회·취소할 수 있다 |
| POL-12 | 안내 문구 | 실패와 지연을 구분하고, 결과마다 '계정이 어떻게 되는지'를 함께 알린다 |

## 상세

### POL-01 대상과 진입 시점
| 항목 | 내용 |
|---|---|
| 정책 | 가입한 회원 누구나 본인확인을 할 수 있다. 의무가 아니다 |
| 진입점 | ① **가입 직후 안내** (신규 가입 시 1회, 바텀시트) ② **마이페이지 > 본인확인하기** (미확인일 때 상시) |
| Why | 본인확인은 서비스의 핵심 가치(정보 공유)와 직접 관련이 없다. 가입 단계에서 강제하면 이탈이 늘고, 그렇다고 아예 진입점이 없으면 아무도 하지 않는다. 그래서 **가장 관심이 높은 순간(가입 직후)에 한 번 권유하고, 이후에는 필요할 때 찾을 수 있는 자리(마이페이지)**에 둔다 |
| 예외 | 가입 직후 안내를 닫거나 '나중에'를 누르면 다시 띄우지 않는다 (반복 노출 피로 방지) |
| 관련 | SC-01, SC-02 / REQ-01, REQ-02 |

### POL-02 미확인 회원의 이용
| 항목 | 내용 |
|---|---|
| 정책 | 본인확인 여부로 막는 기능은 없다 |
| Why | 선택형이라는 약속을 지키려면 불이익이 없어야 한다. 확인 완료에 혜택을 붙일지는 별도 서비스 정책으로 결정한다(오픈 이슈) |
| 관련 | SC-02 / REQ-03 |

### POL-03 진행 중 요청
| 항목 | 내용 |
|---|---|
| 정책 | 회원당 진행 중인 요청은 1건이다. 진행 중에 다시 '본인확인하기'를 누르면 **같은 요청을 이어서** 진행한다 |
| Why | 버튼 연타, 앱 재실행, 다른 기기에서 다시 시도하는 경우마다 요청이 새로 생기면 어떤 결과가 최종인지 알 수 없다 |
| 예외 | 이전 요청이 이미 실패·취소·만료로 끝났다면 새 요청을 만든다. 이전 요청이 앱 밖에서 이미 성공했다면 그 성공을 반영하고 '이미 완료' 안내를 띄운다 |
| 관련 | SC-02, SC-03 / REQ-04 / 시스템: 회원당 진행 중 1건 보장 |

### POL-04 유효시간
| 항목 | 내용 |
|---|---|
| 정책 | 요청 후 **5분**(가정) 안에 인증을 마쳐야 한다. 시간이 지나면 '만료'로 끝나고 계정은 미확인 그대로 유지된다 |
| Why | 오래된 요청이 열려 있으면 엉뚱한 시점의 인증이 계정에 반영될 위험이 있다. 반대로 너무 짧으면 인증 앱을 오가는 사이에 끊긴다 |
| 예외 | 인증기관에서 5분 뒤에 성공한 것은 인정하지 않는다 |
| 운영 | 성공까지 걸린 시간의 p90을 주기적으로 보고 조정한다 (운영 지표 M3) |
| 관련 | SC-04, SC-07 / REQ-06 |

### POL-05 결과 판정
| 항목 | 내용 |
|---|---|
| 정책 | 인증 결과는 **서버가 인증기관에 직접 조회**한다. 그 결과의 **전자서명까지 확인된 경우**에만 인정한다 |
| Why | 앱이 "성공했어요"라고 보내는 값을 믿으면 누구나 확인 완료가 될 수 있다. 인증 화면에서 돌아올 때의 주소(URL)에도 결과를 싣지 않는다 |
| 관련 | SC-05 / REQ-05, REQ-11 |

### POL-06 취소와 이탈
| 항목 | 내용 |
|---|---|
| 정책 | 사용자가 **'취소' 버튼을 눌렀을 때만** 취소로 처리한다. 인증 화면을 닫거나 앱을 나간 것은 **보류**로 보고, 유효시간 안에 돌아오면 이어서 할 수 있다 |
| Why | 실수로 닫았거나 전화를 받은 사용자에게 처음부터 다시 하게 만들 이유가 없다 |
| 예외 | 취소를 누른 순간 인증기관에서 이미 성공이 확정돼 있었다면, 성공이 우선이다 |
| 관련 | SC-03, SC-05, SC-07 / REQ-07 |

### POL-07 지연·장애
| 항목 | 내용 |
|---|---|
| 정책 | 인증기관 응답이 늦거나 연결되지 않으면 **실패로 처리하지 않고** '결과 확인이 지연되고 있어요'로 안내한다. 화면은 자동으로 다시 확인한다 |
| Why | 사용자는 이미 인증을 마쳤을 수 있다. 이 상황을 실패로 보여주면 다시 인증하게 만들거나 불신을 낳는다 |
| 예외 | 유효시간이 지나고 추가로 10분(가정)이 더 지나도 확인하지 못하면 '만료'로 끝낸다. 사용자는 새로 시도할 수 있다 |
| 관련 | SC-05 / REQ-08 |

### POL-08 완료 이후
| 항목 | 내용 |
|---|---|
| 정책 | 확인 완료된 계정은 다시 인증하지 않는다. 로그인할 때마다 본인확인을 다시 묻지 않는다. 마이페이지에는 '본인확인 완료'와 완료 시각을 표시한다 |
| 완료 시각 | 서버가 결과를 확인하고 반영한 시각 |
| 관련 | SC-06, SC-08 / REQ-09 |

### POL-09 탈퇴
| 항목 | 내용 |
|---|---|
| 정책 | 탈퇴하면 진행 중인 요청을 취소로 끝내고, 계정의 확인 상태와 시각을 파기한다. 탈퇴 뒤에 인증이 성공해도 반영하지 않는다. 같은 계정으로 다시 가입하면 미확인부터 시작한다 |
| 관련 | REQ-10 |

### POL-10 개인정보
| 항목 | 내용 |
|---|---|
| 정책 | 서비스에 남기는 것은 **확인 여부와 시각**뿐이다. 이름·생년월일·전화번호·CI·DI·주민등록번호는 받지 않는다. 소셜 로그인으로 받은 프로필(이름·이메일)을 본인확인 결과로 **덮어쓰지 않는다** |
| Why | 목적(확인된 사람인지 구분)에 필요한 최소한만 처리한다 (개인정보 보호법 제16조 취지, [40](40-compliance-analysis.md)) |
| 화면 | 인증 전 안내(SC-03)에서 **저장 항목을 미리 고지**한다 |
| 관련 | SC-03 / REQ-12 |

### POL-11 접근 권한
| 항목 | 내용 |
|---|---|
| 정책 | 인증 요청은 로그인한 본인만 조회·취소할 수 있다. 다른 사람의 요청은 '없는 요청'과 똑같이 응답한다(존재 여부도 숨김) |
| 관련 | REQ-13 |

### POL-12 안내 문구
| 원칙 | 예 |
|---|---|
| 실패와 지연을 구분한다 | 실패: "본인확인에 실패했어요" / 지연: "결과 확인이 지연되고 있어요" |
| 계정이 어떻게 되는지 함께 알린다 | "계정은 미확인 상태로 유지돼요" |
| 선택이라는 점을 드러낸다 | "하지 않아도 서비스를 그대로 이용할 수 있어요" |
| 내부 코드는 보여주지 않는다 | 종료 사유 코드는 사용자 문구로 바꿔서 노출 |
| 다음 행동을 하나만 제시한다 | 실패·만료 → [다시 시도] / 지연 → (자동 재확인) |
