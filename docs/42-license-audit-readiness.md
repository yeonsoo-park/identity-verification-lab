# 42. 인증 라이선스 심사 대응 관점 점검표 (학습용)

> **목적:** 인증센터 업무 중 "인증 라이선스 유지(심사 대응)"를 이해하기 위해 만든 점검표입니다. 운영 통제 영역별로 "심사에서 무엇을 증명해야 할지"를 생각해 보고, 이번 실습에서 그 증적이 어디에 있는지 연결했습니다.
>
> **한계:** 실제 평가 항목 원문은 확보하지 못했습니다. 그래서 아래 표는 전자서명인증업무 운영기준이나 WebTrust 기준의 원문이 아닙니다. 인증기관 운영에서 **일반적으로 다루는 통제 영역**을 기준으로 직접 구성한 표입니다. 실제 대응은 고시 원문과 평가 매뉴얼을 기준으로 해야 합니다.

## 1. 통제 영역별 점검

| 영역 | 심사에서 보여줘야 할 것 (일반론) | 실습 증적 | 수준 |
|---|---|---|---|
| 정책·규격 문서화 | 서비스 규격, 운영 절차가 문서로 있고 최신인가 | [20 연동 가이드](20-partner-integration-guide.md)(버전·변경이력), [30 운영 매뉴얼](30-api-operations-manual.md) | 부분 |
| 문서와 실제의 일치 | 문서대로 운영되는가 | `lab/tools/check_docs.py`(코드↔문서 자동 대조), 생성 문서 | 구현 |
| 키 생성·보관 | 키 생성 절차, 보관 장치, 접근 권한 | `generate-lab-pki.sh`, 개인키 커밋 제외 | 실습 수준 (HSM 없음) |
| 인증서 수명주기 | 발급, 만료 관리, 교체, 폐지 | 유효기간 검증, 교체 절차([21 §5](21-partner-portal-plan.md)), 만료 점검(운영 매뉴얼 §5) | 부분 (폐지 없음) |
| 접근통제 | 권한 분리, 최소 권한 | 본인 요청만 조회, lab 기능 격리, 기동 안전장치 | 부분 |
| 로깅·감사 추적 | 중요 이벤트 기록, 위·변조 방지, 보관 | `IDV_AUDIT` 이벤트 7종 | 부분 (로그 무결성·보관 정책 없음) |
| 무결성 | 전송·저장 데이터 위·변조 방지 | 결과 서명 검증, 요청 ID 대조, 상태 역전 금지 | 구현 |
| 가용성·장애 대응 | 장애 절차, 복구 목표, 훈련 기록 | 런북 A~F, 장애 주입 E2E(DOWN·TIMEOUT·DROP·TAMPER) | 구현 (훈련 자동화) |
| 변경관리 | 변경 전 시험, 승인, 이력 | 변경 관리 절차(운영 매뉴얼 §7), 테스트 34개와 E2E 52개 | 부분 (승인 절차 없음) |
| 개인정보 보호 | 최소 수집, 파기, 안전조치 | [40 컴플라이언스](40-compliance-analysis.md) | 부분 |
| 이용기관 관리 | 제휴 등록, callback·credential 관리 | callback 등록제(`MV9107`), 포털 기획 | 부분 |

## 2. 심사 대응 업무를 자동화할 수 있는 부분 (AX 관점)

| 수작업 | 자동화 아이디어 | 이번 구현 |
|---|---|---|
| 규격 문서와 실제 코드·설정 대조 | 코드에서 사실을 추출해 문서와 비교 | `check_docs.py` |
| 오류코드·API 목록 문서 갱신 | 코드와 OpenAPI에서 생성 | `generate_reference.py` |
| 장애 대응 절차가 실제로 동작하는지 시연 | 장애 주입 시나리오 자동 실행과 결과 기록 | `run_e2e.py` S4·S8 |
| 운영 지표 보고서 | SQL을 정기 실행해 보고 | `lab/ops/metrics.sql` (정기 실행은 미구현) |
| 증적 수집 (로그 발췌, 설정 스냅샷) | 스크립트로 묶어서 수집 | 미구현 (아이디어) |
