# 21. 제휴사 포털 기획 (실습 최소 구현 포함)

> 인증 플랫폼을 이용하는 기관(제휴사)이 **연동 상태를 스스로 확인하고 설정을 관리하도록 돕는 포털**을 기획한 문서입니다.
> 실습에서는 모의 서버의 `GET /mock-idp/portal` 화면 하나만 **읽기 전용**으로 구현했습니다.

## 1. 왜 필요한가 (문제 정의)

연동 과정에서 이용기관이 자주 겪는 문제는 대부분 "어디가 잘못됐는지 모른다"는 데서 시작합니다. 그 결과 플랫폼 운영 담당자에게 문의가 몰립니다.

| 이용기관이 겪는 상황 | 지금 확인하는 방법 | 포털이 있으면 |
|---|---|---|
| 결과 요청에 `MV9107`이 온다 | 담당자에게 문의 | 등록된 callback URL 목록을 직접 대조 |
| 서명 검증이 실패한다 | 담당자에게 문의 | 현재 서명 인증서의 주체·발급자·유효기간·지문을 확인 |
| 사용자가 "인증했는데 반영이 안 됐다"고 한다 | 기관 로그 요청 | 해당 거래의 상태와 완료 시각 조회 |
| 오류가 늘어나는 것 같다 | 감으로 판단 | API별·결과코드별 건수 확인 |

**목표:** 이용기관이 연동 문제를 스스로 진단할 수 있게 해서 문의를 줄이고, 원인을 찾는 시간도 줄입니다.

## 2. 사용자와 권한

| 역할 | 할 수 있는 일 |
|---|---|
| 이용기관 개발자 | 연동 정보·인증서·거래·코드 현황 조회, 테스트 환경 credential 확인 |
| 이용기관 관리자 | 위 기능 + callback URL 변경 신청, 담당자 관리 |
| 플랫폼 운영자(인증센터) | 변경 신청 승인, 인증서 교체 공지, 이용기관별 현황 모니터링 |

## 3. 기능 범위

| # | 기능 | 실습 구현 | 비고 |
|---|---|---|---|
| P1 | 연동 정보 (이용기관 ID, 등록 callback URL, 인증 유효시간, 서명 알고리즘) | **구현** | 읽기 전용 |
| P2 | 결과 서명 인증서 정보 (주체·발급자·유효기간·SHA-256 지문) | **구현** | 인증서 교체를 미리 알리는 용도로도 사용 |
| P3 | 최근 거래 50건 (요청 시각, composite_key, client_request_id, 상태, 만료, 완료) | **구현** | 개인정보는 표시하지 않음 |
| P4 | API별·결과코드별 호출 수 | **구현** | 서버 메모리 기준이라 재시작하면 초기화 |
| P5 | 로그인과 권한별 메뉴 | 기획만 | 실습 포털은 인증이 없음 (localhost 전용) |
| P6 | callback URL 변경 신청 → 운영자 승인 | 기획만 | 오픈 리다이렉트를 막으려면 승인 절차가 필수 |
| P7 | credential 재발급 (테스트/운영 분리) | 기획만 | 재발급 직후 기존 값의 유예기간 정책이 필요 |
| P8 | 인증서 교체 일정 공지와 새 Root·서명 인증서 미리 배포 | 기획만 | §5 |
| P9 | 연동 가이드·결과코드·변경 이력 | 링크만 | [20-partner-integration-guide.md](20-partner-integration-guide.md) |
| P10 | 오류율이 임계치를 넘으면 담당자에게 알림 | 기획만 | 운영 매뉴얼의 지표와 연결 |

## 4. 화면 구성 (실습 구현 기준)

```
┌ 제휴사 포털 (실습) ─────────────────────────────────────┐
│ [연동 정보]  이용기관 ID · 등록 callback URL · 유효시간 · 서명 알고리즘 │
│ [결과 서명 인증서] subject / issuer / notBefore / notAfter / SHA256 지문 │
│ [최근 거래]  상태별 건수 요약 + 50건 표                                  │
│ [API 호출·결과코드 현황] API · 결과코드 · 의미 · 건수                    │
└──────────────────────────────────────────────────────────┘
```

확인 방법: `./lab/run-lab.sh` 실행 후 http://localhost:18090/mock-idp/portal 에 접속합니다. 자동 확인은 E2E S8에서 합니다(200 응답과 서명 인증서 표시 여부).

## 5. 운영 정책 (기획안)

| 정책 | 내용 |
|---|---|
| callback URL | 정확히 일치하는 값만 허용합니다(와일드카드 금지). 변경은 신청 → 운영자 승인 → 반영 순서입니다. 실습은 환경변수 `MOCK_IDP_ALLOWED_CALLBACKS`로 대신합니다 |
| 서명 인증서 교체 | 만료 전에 미리 공지하고 새 인증서를 포털에 게시합니다. 새 키로 서명하기 시작하는 전환일을 알리고, 일정 기간은 이용기관이 새 인증서와 기존 인증서를 모두 신뢰하도록 안내합니다. 실습에서는 Root CA를 신뢰 기준으로 삼아 서명 인증서를 바꿔도 이용기관 쪽 변경이 필요 없게 했습니다 |
| 개인정보 | 포털에는 거래 식별자와 상태만 표시합니다. 이용기관의 회원 식별값(실습에서는 client_request_id)도 일부만 보여 줍니다 |
| 감사 | 포털에서 일어나는 설정 변경은 모두 감사 로그 대상입니다 (기획만) |

## 6. 성공 지표 (가정)

| 지표 | 측정 방법 |
|---|---|
| 연동 문의 건수 | 오픈 전후 문의 티켓 수 비교 |
| 연동 완료 기간 | 테스트 credential 발급부터 운영 전환까지 걸린 일수 |
| 연동 오류율 | 결과코드 `MV9104`, `MV9107`, `MV9200` 비율 (P4) |
