# 11. 화면 흐름과 문구 (UX Copy) 명세

> 네이티브 앱 화면은 범위 밖입니다. 아래 명세대로 최소 데모 화면(`/lab/identity-demo`)을 구현해 두었습니다. 앱 개발자에게 전달하는 분기 기준으로 쓰는 문서입니다.

## 1. 화면 목록

| ID | 화면 | 진입 | 호출 API |
|---|---|---|---|
| SC-1 | 가입 완료 안내 (선택형 진입점) | 로그인 응답 `isNewUser=true` | – |
| SC-2 | 마이페이지 본인확인 영역 | 마이페이지 진입 | `GET /members/me` |
| SC-3 | 외부 인증 화면 (기관 표준창) | SC-1/SC-2에서 시작 | `POST .../identity-verifications` → `authUrl` |
| SC-4 | 결과 확인 중 | 외부 화면에서 복귀 | `GET .../{id}` (2초 간격) |
| SC-5 | 결과 안내 | SC-4 종료 | – |

## 2. 응답에 따른 화면 분기

| API 응답 | 다음 화면 | 문구 |
|---|---|---|
| `members/me` `UNVERIFIED` | SC-2 버튼 | **본인확인하기** |
| `members/me` `VERIFIED` | SC-2 배지 | **본인확인 완료** · 완료 시각 `yyyy-MM-dd HH:mm` |
| 생성 201/200 + `authUrl` | SC-3 | (이동) |
| 생성 409 | SC-2 새로고침 | "이미 본인확인을 마쳤어요" |
| 생성 503 | SC-2 유지 | "인증기관 연결이 원활하지 않아요. 잠시 후 다시 눌러주세요." |
| 조회 `PENDING` | SC-4 | "인증을 기다리는 중이에요." |
| 조회 `SUCCEEDED` | SC-5 | "본인확인이 완료됐어요." |
| 조회 `FAILED` | SC-5 | "본인확인에 실패했어요. 다시 시도할 수 있어요." |
| 조회 `CANCELLED` | SC-5 | "본인확인을 취소했어요. 계정은 미확인 상태로 유지돼요." |
| 조회 `EXPIRED` | SC-5 | "인증 유효시간이 지났어요. 다시 시도해주세요." |
| 조회 503 / 502 | SC-4 유지 + 자동 재조회 | "결과 확인이 지연되고 있어요. 자동으로 다시 확인할게요." |
| 조회 401 | 로그인 | "로그인이 만료됐어요. 다시 로그인하면 이어서 확인할게요." |
| 조회 404 | SC-2 | "요청을 찾을 수 없어요." |

## 3. 문구 원칙

1. **실패와 지연을 구분합니다.** 503과 502는 "실패했어요"가 아니라 "지연되고 있어요"라고 씁니다. 사용자가 다시 인증하지 않아도 됩니다.
2. **계정이 어떻게 되는지 알려줍니다.** 취소나 만료 시 "미확인 상태로 유지돼요"를 넣어, 불이익이 없다는 점을 분명히 합니다.
3. **선택이라는 점을 드러냅니다.** SC-1에는 "본인확인은 선택이에요. 하지 않아도 서비스를 그대로 이용할 수 있어요."를 넣고, "나중에 할게요" 버튼을 같은 크기로 둡니다.
4. **실습임을 표시합니다.** 모의 인증 화면 상단 배너에는 항상 "실습용 모의 인증이며 실제 본인확인이 아닙니다"를 표시합니다.
5. **원인 코드는 사용자 문구로 바꿔 보여줍니다.** `endReason` 같은 내부 코드는 데모에서만 괄호로 보여 주고, 실제 앱에서는 숨깁니다.

## 4. 동작 원칙

| 원칙 | 이유 |
|---|---|
| 화면을 닫을 때는 cancel API를 부르지 않음 | 실수로 닫은 경우에도 이어서 진행할 수 있게 |
| 취소 버튼은 PENDING일 때만 노출 | 종료된 요청에 취소를 누르는 혼란 방지 |
| verificationId를 앱 저장소에 보관 | 복귀하거나 재로그인한 뒤에도 같은 요청 조회 |
| 결과는 복귀 URL이 아니라 서버 조회로 판단 | 클라이언트 값 불신 원칙 |
